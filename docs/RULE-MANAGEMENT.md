# 规则管理设计（参考 Clash 系客户端）

- 日期：2026-11-14
- 目标：像 Clash for Windows / Verge / Android 那样，让用户能自行添加「某域名/IP 走直连或代理」的规则
- 状态：设计梳理，未实施

---

## 1. 可行性结论

**可以，但内核没有规则 CRUD 接口**，只能走「改配置 + 重载」：

| 接口 | 能力 | 实测 |
|---|---|---|
| `GET /rules` | 只读，返回当前规则列表 | 200，516 条 |
| `PUT /configs?force=true` | 按文件路径重载配置 | **204**，规则数不变，进程不重启 |
| `POST /restart` | 重启内核（较重） | 200，PID 不变（exec） |

所以方案是：

1. 自定义规则独立存储（不写进订阅原文）
2. 把自定义规则**插到 `rules:` 最前面**
3. 调用 `PUT /configs` 重载生效
4. 失败则用备份回滚

## 2. 参考 Clash 的页面设计

### 2.1 订阅页

| 元素 | 说明 |
|---|---|
| 配置卡片 | 名称、订阅 URL、节点数、更新时间 |
| 操作 | 更新、编辑、删除、切换当前配置 |
| 自动更新 | 间隔（如 24h），到期自动拉取 |

我们现状：只有 URL 输入 + 导入，缺名称/更新时间/自动更新。

### 2.2 节点页

| 元素 | 说明 |
|---|---|
| 分组切换 | 已有 |
| 搜索 / 延迟排序 | 已有 |
| 测速 | 已有（整组测速） |
| 节点选择 | 已有 |
| 待补 | 隐藏不可用节点、按地区/关键词快速筛选 |

### 2.3 规则页（重点）

Clash 系的规则页一般有两块：

1. **内置规则**：来自订阅，只读，可按类型/关键字搜索（我们已有）
2. **自定义规则**：可增删改、可排序、可启用/禁用

自定义规则行：

```
[开关] DOMAIN-SUFFIX  example.com      → DIRECT      ↑ ↓ ✕
[开关] IP-CIDR       10.0.0.0/8         → 直连        ↑ ↓ ✕
[开关] DOMAIN        ads.example.com   → REJECT      ↑ ↓ ✕
```

「添加」对话框：

| 字段 | 选项 |
|---|---|
| 类型 | DOMAIN / DOMAIN-SUFFIX / DOMAIN-KEYWORD / IP-CIDR / IP-CIDR6 / SRC-IP-CIDR（可选） |
| 内容 | 域名或 CIDR |
| 目标 | DIRECT / REJECT / 代理组 / 具体节点 |
| 额外 | IP 类自动加 `no-resolve` |

### 2.4 快捷入口（Clash Verge 有）

连接列表长按/点击某条连接：

```
此域名 → 直连
此域名 → 走代理（当前组）
此 IP  → 直连
```

自动生成对应规则并生效，省去手输。

## 3. 数据与注入方案

### 3.1 存储

- App 内保存 `List<CustomRule>`（JSON 文件或 SharedPreferences）
- 字段：`id / type / value / target / enabled / createdAt`
- **不修改订阅原文**，订阅更新不会丢失自定义规则

### 3.2 注入

在 `config.yaml` 的 `rules:` 后插入标记块：

```yaml
rules:
  # >>> custom rules (managed by app)
  - DOMAIN-SUFFIX,example.com,DIRECT
  - IP-CIDR,10.0.0.0/8,DIRECT,no-resolve
  # <<< custom rules
  # 以下为订阅自带规则
  - GEOIP,CN,DIRECT
  ...
```

- 每次变更：重写标记块 → 备份 → 重载 → 失败回滚
- 订阅导入后：自动重新注入（导入流程在 App 内，可控）

### 3.3 生效与回滚

```
写临时文件 → 校验（YAML 基本结构 / 策略名存在）
  → cp 备份 → 替换 config.yaml
  → PUT /configs?force=true
  → 204 成功；否则恢复备份并重载
```

## 4. 冲突与风险

| # | 风险 | 处理 |
|---|---|---|
| 1 | 订阅更新覆盖配置 | 导入后自动重注入；规则独立存储 |
| 2 | 写坏配置导致内核起不来 | 备份 + 回滚 + 重载结果校验 |
| 3 | 规则顺序错 → 不生效 | 自定义规则始终置顶 |
| 4 | `mode: global/direct` 时规则不生效 | 规则页提示当前模式，或引导切回 rule |
| 5 | fake-ip 下 IP 规则对域名连接无效 | IP 类自动 `no-resolve`，并在说明中注明 |
| 6 | 策略名不存在（节点/组改名） | 保存前用 `/proxies` 校验，失效规则标红 |
| 7 | PROCESS-NAME 在网关场景无意义 | 首版不提供（热点客户端流量没有本机进程） |
| 8 | 规则过多影响匹配性能 | 线性匹配，数百条无感；超过 1000 条提示 |
| 9 | 与订阅自带规则冲突 | 自定义置顶即可覆盖；UI 标注“优先于订阅规则” |

## 5. 建议首版范围

| 功能 | 优先级 |
|---|---|
| 自定义规则：增 / 删 / 启用停用 / 上移下移 | P0 |
| 类型：DOMAIN / DOMAIN-SUFFIX / DOMAIN-KEYWORD / IP-CIDR / IP-CIDR6 | P0 |
| 目标：DIRECT / REJECT / 代理组 / 节点 | P0 |
| 应用（注入 + 重载 + 回滚） | P0 |
| 连接页快捷“此域名直连/走代理” | P1 |
| SRC-IP-CIDR（按客户端 IP 分流） | P1（网关场景很有用） |
| DST-PORT / PROCESS-NAME | P2 |
| 订阅名称 / 更新时间 / 自动更新 | P1 |
