# 逻辑梳理与优化清单（v2.7.0）

## 1. 数据流

```
UI (Compose) ── StateFlow ── ViewModel ── Repository ── ShellExecutor(su) ─┐
                    ▲                          │                         ├─ mihomo 进程 / iptables
                    │                          └─ MihomoApi (HTTP 9090) ─┘
                    │
              SettingsStore (SharedPreferences)
                    ▲
        GatewayService（前台服务 / 开机自启 / 自动更新循环 / 网络事件）
```

关键状态：

| 状态 | 权威来源 | 备注 |
|---|---|---|
| 运行/停止 | `desired_running` + 实际 pid | 通知停止与 QS 磁贴都会写 `desired_running` |
| 模式 | `/configs.mode` | UI 通过 PATCH 修改 |
| 地址族 | `gateway.conf IP_MODE` + 每节点 `ip-version` | 与 `/configs.ipv6` 无关 |
| IPv6 拦截 | `gateway.conf BLOCK_IPV6` | 由 apply.sh 落到 ip6tables |
| 订阅 | `settings.subscriptionUrl`（当前）+ `subscriptions`（列表） | 两处需保持同步 |
| 规则 | `custom_rules.json` + `config.yaml` 标记块 | 应用时注入并热重载 |

## 2. 发现的问题

### P0（会导致状态不一致 / 功能失效）

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| 1 | 删除当前订阅时未清空 `subscriptionUrl` | SettingsViewModel.deleteSubscription | 自动更新仍会去拉已删除的订阅 |
| 2 | 旧的「导入订阅」入口不写入订阅列表 | SettingsViewModel.importSubscription | 导入成功但「已保存订阅」为空，activeSubId 为空 |
| 3 | 设备过滤 chips 只在拓扑/图形模式渲染 | ConnectionsScreen | 在拓扑页选中设备后切到「列表」，列表仍被过滤但无清除入口 |
| 4 | 恢复备份丢失规则启用状态 | SettingsViewModel.restoreBackup | 所有规则被恢复为 enabled=true |
| 5 | 恢复备份不写 gateway.conf | 同上 | ipMode 只存进设置，实际网关仍是旧值，直到手动切换 |

### P1（体验/性能）

| # | 问题 | 说明 |
|---|---|---|
| 6 | 暂停连接列表时仍在轮询 | `paused` 只冻结数据，`startPolling` 未停；可暂停时停止 1s 轮询 |
| 7 | QS 磁贴状态可能过期 | 只在 `onStartListening` 刷新，App 内启停不会同步磁贴 |
| 8 | 通知「停止网关」后服务常驻「待命」 | 可接受，但通知文案与操作按钮未更新 |
| 9 | 规则保存失败静默 | `RuleStore.save` 仅打日志，UI 仍提示成功 |
| 10 | 收藏用逗号串存储 | 节点名含逗号会被拆坏，建议 JSON 数组 |
| 11 | 设置页地址族/模式可能滞后 | 外部脚本改了 gateway.conf 后，UI 值不变（仅服务启动时同步） |
| 12 | 今日流量为采样累加 | 以 `/traffic` 每秒速率直接累加，采样抖动会有误差 |
| 13 | 多订阅切换无进度反馈 | `activateSubscription` 未设置 busy，重复点击会并发下载 |

### P2（健壮性）

| # | 问题 |
|---|---|
| 14 | 备份不包含收藏/订阅列表/今日流量，仅在文档说明 |
| 15 | 设备历史未持久化（重启丢失，已在 BACKLOG） |
| 16 | 注入规则依赖 `rules:` 精确匹配，块状写法异常时只能靠回滚 |
| 17 | 整组测速失败时逐节点兜底会发 40+ 请求，缺少并发上限 |

## 3. UI 优化建议

| 页面 | 现状 | 建议 |
|---|---|---|
| 订阅管理 | 顶部「订阅配置」+ 下方「已保存订阅」两套导入入口 | **合并**：删除顶部 URL 输入，统一用「添加订阅」；列表行加「更新」按钮 |
| 订阅管理 | 无激活标识 | 激活行显示「当前」标签 + 高亮 |
| 连接 | 排序 chips 只在拓扑表格 | 列表模式也提供排序（按流量/时间）；设备 chips 提到搜索框上方全局显示 |
| 连接 | 设备 chips 不可见时过滤残留 | chips 常驻，并显示「筛选中：x.x.x.x」+ 清除 |
| 代理 | 延迟只有文字 | 加延迟条（颜色+长度），更直观 |
| 代理 | 单列 | 可选紧凑双列（一屏更多节点） |
| 规则 | 添加对话框 6 个类型 chip 横向溢出 | 改成下拉选择；目标策略支持搜索 |
| 日志 | 工具栏 LazyRow 把「导出」挤出屏幕 | 工具栏改两行或图标按钮 |
| 概览 | 当前节点不可点 | 点击跳转代理页并定位分组 |
| 概览 | 今日流量无趋势 | 增加近 7 天柱状（本地累计） |
| 设置 | 条目较多 | 加设置搜索；「管理」区加图标 |
| 全局 | 空态/错误提示偏弱 | 统一带「重试」按钮的错误态 |

## 4. 建议实施顺序

### 第一批（P0，约 0.5 天）

1. 删除当前订阅时清空 `subscriptionUrl`，并停止自动更新
2. 旧导入入口并入订阅列表（或直接移除顶部输入框）
3. 设备 chips 移到全局位置，列表模式也可见
4. 恢复备份：保留 enabled 状态 + 恢复后调用 `gateway.setIpMode`

### 第二批（P1，约 1 天）

5. 暂停时停止轮询
6. QS 磁贴随启停刷新
7. 多订阅切换加 busy 与进度
8. 收藏改 JSON 存储（兼容旧逗号串）
9. 通知停止后更新文案与按钮

### 第三批（UI，约 1 天）

> 进度：10（订阅入口合并 + 当前标识）、11（日志工具栏）、12（规则对话框）与 13 的延迟条均已完成（v2.9.3–v2.9.5）；仅剩 13 的双列布局未做（节点名偏长，暂保持单列）。

10. 订阅页合并入口 + 激活标识
11. 日志工具栏改版
12. 规则对话框类型下拉 + 目标搜索
13. 延迟条 / 双列（可选）

## 5. 结论

核心链路（启停、网关规则、规则注入、订阅更新）是稳定的；问题集中在**多入口状态同步**（订阅、过滤、备份）和**UI 反馈**上。建议先做 P0 四项，都是小改动、低风险。
