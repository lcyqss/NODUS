# ADR 0012：设备策略的延迟阈值回落

- 状态：已接受
- 日期：2026-11-15

## 背景

v1 的 fallback 组只判断「节点是否存活」，无法表达「香港延迟太高就切新加坡」。mihomo 的 url-test/fallback 没有绝对延迟阈值参数。

## 决策

1. 策略设置 maxDelayMs 后，根组由 fallback 改为 select，成员仍是优先组与回落组。
2. App 侧调度：
   - 应用策略后立即评估一次
   - GatewayService 每 60 秒评估一次
   - 通过 /group/<优先组>/delay 取最优延迟；大于阈值或无可用节点时 select 回落组，否则 select 优先组
3. maxDelayMs = 0 时保持原 fallback 行为（只按存活）。
4. 安全保护：策略能匹配到节点但设备全部离线时，拒绝重写配置，保留现有策略块，避免临时离线把规则清空。
5. 订阅安装流程仍只写配置，延迟评估由应用后/定时任务完成。

## 后果

- 阈值策略的根组是 select，切换依赖 App 进程；内核单独运行时保持上次选择。
- 评估频率 60 秒，切换有最多约 1 分钟延迟。
- 设备离线不会清空已有 __dev_ 组与 SRC-IP 规则。
