# ADR 0009：订阅作为聚合根

- 状态：已接受
- 日期：2026-11-15

## 背景

订阅原先只有 URL 与一份全局自动更新间隔，Provider、名称、更新状态散落在设置页与全局字段里。多订阅时无法解释“某个订阅自己的更新间隔/来源”。

## 决策

1. 订阅是聚合根：id / name / url / autoUpdateHours / lastUpdateAt / nodeCount 都属于订阅对象。
2. Provider 是订阅配置的**派生只读元数据**（解析订阅 YAML 得到），不单独持久化；健康检查只对当前生效订阅可用。
3. 每个订阅有独立缓存 iles/profiles/<id>.yaml；后台更新先写缓存，只有当前订阅才热重载内核。
4. 自动更新调度属于应用基础设施（GatewayService），不在订阅对象里；订阅只保存间隔。
5. 管理订阅是集合视图；订阅详情负责改名/链接/间隔/Provider/删除；代理页弹层只负责切换、更新与间隔快捷设置。
6. 删除当前订阅时自动切换到剩余第一个；没有剩余则保留旧配置。

## 后果

- 设置页不再有订阅相关入口。
- 非当前订阅的“立即更新”只更新缓存，不触碰运行中的内核。
- 切换订阅优先用缓存，缓存缺失或按间隔过期才重新下载。
## 追补（v2.13.1）

- 集合页取代底部弹层：切换与管理都在订阅管理页，编辑页负责对象属性。
- 同 URL 允许并存（不再按 URL 去重），避免添加订阅时覆盖已有条目。
- 代理页订阅行只显示“N 个订阅 / M 个已启用”，不出现具体订阅名。
