# ADR 0068：配置备份的编解码与恢复流程

- 状态：已接受
- 日期：2026-11-17
- 关联：v2.63.0

## 背景

备份恢复连续出现三类问题：

1. 恢复后规则页仍显示「有未应用的改动」，但内核里规则其实已经生效
2. 设备策略提示「引用的标签已被删除」，实际是订阅缓存缺失导致节点目录为空
3. 恢复流程中规则 / 策略应用失败被 `runCatching` 吞掉，界面仍提示「配置已恢复」

根因分别是：页面状态与仓库应用状态不同步、备份只存订阅元数据、恢复流程缺少失败上报。

## 决策

### 1. 编解码独立成 `BackupCodec`

- `encode(settings, rules)`：生成 schema v2 JSON
- `decode(raw)`：解析为 `Backup(settings, rules, rulesPresent)`
- 缺失字段解析为 `null`，恢复时保留当前值（而不是回退成「当前值」的隐式逻辑）
- 不依赖 Android Context / 存储，可单元测试

### 2. 恢复顺序固定

```text
写入设置（含订阅列表与 activeSubId）
→ 切换 / 重新下载当前订阅（节点目录为空时强制重试）
→ 应用地址族、IPv6 拦截、IPv6 代理
→ 应用自定义规则
→ 应用设备策略
```

任一步失败都会抛出，恢复界面显示具体错误，不再「假成功」。

### 3. 规则应用状态由仓库广播

`RuleRepository.applyState` 暴露 `generation + 快照`；任何调用方（恢复备份、订阅切换）
完成 `apply()` 后，规则页据此刷新 `dirty`，不再依赖页面自己判断。

### 4. 节点缺失的判定

- 订阅缓存缺失：恢复时自动 `fetchToCache` 一次，仍为空则报错
- 节点目录为空：设备策略提示「订阅节点未加载，请在订阅管理更新」
- 只有确实引用了不存在的标签，才提示「引用的标签已被删除」

## 结果

- 新增 5 个 `BackupCodecTest` 用例（字段完整、旧备份兼容、非法 JSON、未知规则类型、订阅名解析）
- 恢复备份真机回归通过：规则自动生效、设备策略节点恢复
- CI 在发布前运行单元测试，避免 schema 回归

## 权衡

- 备份仍然只保存订阅元数据，不保存订阅缓存（缓存可能很大且随时可重新下载）
- 因此恢复后需要一次网络请求才能恢复设备策略的节点匹配
