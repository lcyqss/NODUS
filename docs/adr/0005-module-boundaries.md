# ADR 0005：模块边界与单向依赖

- 状态：已接受
- 日期：2026-11-14

## 背景

早期单页原型中，UI 直接调用 `Root.run()` 执行脚本、直接拼 shell 命令查询状态，
数据来源同时存在「shell 文本解析」和「HTTP API」两条路径。继续演进会出现：

- 界面逻辑与系统操作耦合，换页面要改命令
- 状态来源不一致，排查时无法判断哪条路径为准
- 新增功能容易以「打补丁」方式散落在 Activity 里

## 决策

采用三层结构 + 接口隔离 + 单一组合根：

```
L2 ui  →  L1 data（接口）  →  L0 core（基础设施）
```

1. **UI 不得直接 root / HTTP**，只依赖 L1 接口
2. **L1 通过 `ShellExecutor` 接口触达 root**，不直接调用 `ProcessBuilder`
3. **L0 不含业务判断**，只提供能力
4. **唯一组合根** `di/AppContainer`，手工依赖注入，不引入 DI 框架
5. 依赖方向违反即评审不通过

## 理由

- 可测试：Fake ShellExecutor / MockWebServer 即可覆盖大部分逻辑
- 可替换：内核 API 或脚本实现变化时，UI 不受影响
- 可排查：每层有独立日志 Tag 与 traceId
- 避免过度设计：单模块 + 包级分层，不拆 Gradle module、不引入 Hilt

## 后果

- 文件数量增加，但职责清晰
- 新增功能需先判断落点（见设计文档第 14 节）
- 组合根需要手工维护依赖顺序
