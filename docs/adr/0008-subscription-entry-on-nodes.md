# ADR 0008：订阅入口放在节点页

- 状态：已接受
- 日期：2026-11-15

## 背景

订阅原先藏在「设置 → 订阅 → 订阅管理」，而节点页负责分组与节点选择。按 Clash 系客户端（CMFA、Clash for Android、Clash Verge）的习惯，「配置 / Profiles（订阅）」是**内容来源**的一级入口，代理/节点页只负责在已加载的内容里选节点。

我们只有 5 个 Tab（首页 / 节点 / 分流 / 连接 / 设置），加第 6 个 Tab 不划算；但订阅也不该继续留在设置里——它既不是偏好设置，入口也太深。

## 决策

1. 节点页标题下加一行**订阅切换条**：显示当前订阅名与节点数，点击打开底部弹层。
2. 弹层只做三件事：**切换订阅、更新当前订阅、进入订阅管理**。
3. 添加 / 删除订阅放在**订阅管理页**（从弹层进入），保证同一动作只有一个入口。
4. 设置页移除「订阅管理」，只保留**自动更新频率**与**节点来源（Provider）**。
5. 切换/更新订阅走内核 API **热重载**，并保留当前地址族；内核未运行时只落盘，自定义规则用 `injectOnly` 写入，等下次启动生效。

## 理由

- 与 Clash 心智一致：订阅是内容来源，切订阅会换掉整套分组/规则，不适合和「运行模式」这类开关混在设置里。
- 不加 Tab：节点页只多 40–48dp 一行，主列表仍占绝大部分。
- 防误触：切换订阅是重操作（下载 + 热重载），放在弹层里点击，而不是横向 chips 直接切换。
- 入口唯一：设置不再有订阅管理；添加/删除只在管理页。

## 后果

- 节点页需要订阅级 busy 状态，切换成功后要刷新代理列表（URLTest 组还要等首次测速才有 `now`，实现里补刷一次并在必要时主动测速）。
- 手动切换与后台自动更新可能并发写配置：`ProfileRepositoryImpl.install()` 用 `Mutex` 串行化。
- 订阅导入不再强制 `set-ipver auto`，改为沿用 `gateway.conf` 里的地址族；内核停止时导入不再报“新配置无法启动”，也不会顺手拉起内核。
- 删除当前订阅只清设置，不改内核配置：旧节点仍然生效，直到切换或更新订阅；UI 文案已明确提示。
