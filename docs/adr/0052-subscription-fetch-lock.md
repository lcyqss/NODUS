# ADR 0052：订阅下载按 ID 串行化

- 状态：已接受
- 日期：2026-11-16

## 问题

自动更新、手动全部更新、保存并更新、切换订阅都可能同时触发 etchToCache。

原有 installMutex 只保护安装，不保护下载和缓存写入，存在：

- 同一订阅重复下载
- .tmp 缓存竞争
- lastUpdateAt / 
odeCount 互相覆盖

## 变更

- 增加 16 个下载锁（按订阅 ID 哈希取模）
- etchToCache 在锁内执行完整流程：
  - 下载
  - 解析
  - 写临时文件/替换缓存
  - 更新时间元数据
- 不同订阅仍可并行；同一订阅串行

## 结果

同一订阅的自动/手动更新不会并发写缓存；不会无限创建下载任务。
